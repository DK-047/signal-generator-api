# Версии и совместимость

[← К оглавлению](../../README.md)

## Две версии

| Где | Пример | Что означает |
|---|---|---|
| Путь запроса | `/v1/...` | **Мажорная версия API.** Меняется только при несовместимых изменениях |
| `info.version` в `openapi.yaml` | `2.1.0` | **Версия документа-контракта.** Растёт при любых правках описания, в том числе совместимых |

Документ версии 2.1.0 описывает API `/v1` — это не противоречие.

## Совместимые изменения (без смены `/v1`)

- Новые эндпоинты (так в 2.1.0 появился `GET /configuration`).
- Новые **необязательные** поля в ответах.
- Новые значения перечислений в ответах: `state`, `connectivity`, `status` команды,
  `code` ошибки, `failure.code`.
- Новые необязательные параметры запроса и заголовки.

## Несовместимые изменения (новая мажорная версия, `/v2`)

- Удаление или переименование полей, эндпоинтов, параметров.
- Изменение типа поля или смысла значения.
- Новое **обязательное** поле в запросе.
- Смена способа аутентификации или структуры URL.

## Как написать устойчивого клиента

| Правило | Пример |
|---|---|
| Игнорируйте неизвестные поля ответа | Не валидируйте ответы схемой с запретом лишних полей |
| Неизвестный `state` | Обрабатывайте как `ERROR` |
| Неизвестный `connectivity` | Обрабатывайте как `UNKNOWN` |
| Неизвестный `status` команды | Считайте промежуточным, продолжайте опрос |
| Неизвестный `code` ошибки | Обрабатывайте по HTTP-статусу |
| Не полагайтесь на `message` | Текст может меняться |

```javascript
// Плохо: упадёт на новом значении
if (!["IDLE", "READY", "BUSY", "ERROR"].includes(status.state)) throw new Error("bad state");

// Хорошо: неизвестное значение имеет безопасную трактовку
const KNOWN = new Set(["IDLE", "READY", "BUSY", "ERROR"]);
const state = KNOWN.has(status.state) ? status.state : "ERROR";
```

## История изменений контракта

### 2.1.0

- Добавлен `GET /v1/devices/{deviceId}/configuration` — чтение действующей конфигурации.
- Новый код ошибки `IDEMPOTENCY_REQUEST_IN_PROGRESS` (409).
- Уточнены правила `Idempotency-Key`: запоминается только принятая команда (`202`);
  ключ не может быть пустым.
- Ответ `401` содержит заголовок `WWW-Authenticate`.
- Зафиксировано разграничение `400` (разбор) и `422` (проверка).
- Описаны правила совместимости и обработки неизвестных значений перечислений.
- В схеме `Command` формально закреплено, когда есть `completedAt` и `failure`.

### 2.0.0

- Исходная версия контракта `/v1`.
